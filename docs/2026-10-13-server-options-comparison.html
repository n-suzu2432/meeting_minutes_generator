バックエンドの置き場所を、どこにするか

自動議事録ツール(会議の録音・録画から議事録を作る)のバックエンドを、どのサービスに置くのがよいかを比べた資料です。自分用に使う場合と、クライアントに提出する場合の両方を想定しています。

料金と仕様の確認日: 2026年10月13日(各社の公式ページ) / 円換算: 1ドル=158.5円

相談したいこと

  1. クライアントに提出する場合、どこに置くのが一般的か。今の自分の案は「今のコードのまま Fly.io(東京)」か「Google Cloud Run(東京)」です。
  2. サーバーと API キーの名義は、自分とクライアントのどちらにすべきか。自分名義だと利用料が自分に請求され続けます。
  3. 書き直して1か所にまとめる(Vercel または Cloudflare)価値はあるか。管理は楽になりますが、Python のバックエンドを TypeScript で作り直す規模です。
  4. ログインがないまま提出してよいか。今は URL を知っていれば誰でも使えて、サーバーの API キーの料金がかかります。
  5. 会議の音声を外部の AI に送ることを、クライアントにどう説明・合意するか。

このツールがサーバーに求める条件

  • ffmpeg が必要: 音声の変換と分割に使うため、Docker で動かせるサービスが向いています。
  • 処理が数分かかる: 1時間の録音で数分。途中で接続を切られないことが必要です。
  • 大きなファイルを受け取る: 今の上限は200MB・120分です。会議の録画(mp4)は1時間で100〜400MB程度になります。
  • 使う頻度は低い: 月に数本〜数十本。使っていない間は止まって課金されない方式が合います。
  • 辞書を保存している: 誤字置換の辞書をサーバー内のファイルに保存しています。再起動でファイルが消えるサービスでは、保存先の変更が必要です。

現状: フロントエンドは Vercel、バックエンドは Render に置く方針で設定ファイル(render.yaml)まで用意済み。実際のデプロイはまだしていません。

それぞれのメリットとデメリット

今のコードをそのまま置く

Render(無料プラン)

0円

メリット

  • 設定ファイルが用意済みで、すぐ始められる
  • 費用がかからない
  • メモリを抑える処理がすでにコードに入っている

デメリット

  • 15分使わないと止まり、次の起動に約1分かかる
  • メモリ512MB・CPU 0.1コアと小さく、長い録音で落ちる可能性がある(未検証)
  • 再起動や停止でファイルが消えるため、登録した辞書が残らない
  • 日本のリージョンがない

Fly.io(東京)

常時起動 約1,400円 メモリ1GBの場合。512MBなら約770円

メリット

  • 東京に置けるので、アップロードが速く「国内保管」と説明できる
  • 今の Dockerfile のまま動かせる
  • 使っていない間は自動停止にでき、その間はほぼ課金されない
  • 常時起動にすれば、起動待ちがない

デメリット

  • 無料枠がなく、カード登録が必要
  • 設定はコマンド操作が中心
  • 大手クラウドほどの知名度はなく、クライアント側の審査で説明が必要な場合がある

Railway(Hobby プラン)

約790円 5ドル固定、利用料5ドル分込み

メリット

  • GitHub をつなぐだけで動き、設定がいちばん簡単
  • 5〜10分使わないと自動でスリープする機能がある
  • メモリを大きく取れる

デメリット

  • 使わない月も5ドルかかる
  • スリープからの最初のアクセスは遅く、失敗することがある
  • 日本に置けるかは未確認

Cloudflare Containers

約790円 Workers 有料プラン5ドルが必須

メリット

  • 今の Docker 構成をほぼそのまま動かせる
  • 使っていない間は止まり、月数十本なら付属の枠に収まる見込み
  • 辞書の保存先に Cloudflare の無料ストレージを使える

デメリット

  • コンテナの手前に中継用のプログラムを書く必要がある
  • 1回のアップロードは100MBまで(今の上限200MBを下げる必要)
  • 安い構成は CPU が4分の1コアで、音声変換が遅い可能性がある(未検証)

一部を作り替えて置く

Google Cloud Run(東京)

ほぼ0円の見込み 無料枠の数字は未確認

メリット

  • 大手クラウドなので、クライアントの社内審査に通しやすい
  • 東京リージョンがある
  • 使った分だけの課金。メモリは最大32GB、1回の処理は60分まで

デメリット

  • 1回のアップロードが32MBまで。会議の録画はほぼ入らない
  • 回避には「ブラウザで音声だけ取り出して送る」などの改修が必要
  • 初期設定(プロジェクト、権限、課金)が他より重い

書き直して1か所にまとめる(バックエンド用のサーバーをなくす)

Vercel に一本化

自分用 0円 / クライアント利用 約3,200円 Pro 1人20ドル

メリット

  • デプロイ・URL・設定が1か所で済む
  • 起動待ちがない
  • 今のフロントエンド(Next.js)がそのまま動く
  • 映像をサーバーに送らずに済む

デメリット

  • Python のバックエンドを TypeScript で作り直す
  • 無料プランは個人・非商用のみ
  • 1回に送れるのは4.5MBまで。ブラウザで分割して送る作りが必要
  • 1回の処理は無料プランで5分まで(Pro は約13分)
  • 辞書の保存先を別に用意する必要がある

Cloudflare に一本化(Workers)

約790円が現実的 無料プランは計算時間が1回10ミリ秒

メリット

  • 1回100MBまで送れるので、圧縮した音声を分割せずに送れる
  • 接続が続く限り処理時間の上限がない
  • クライアント利用でも Vercel より安い
  • 辞書は無料のストレージで足りる

デメリット

  • Python のバックエンドを TypeScript で作り直す
  • メモリが128MBで、ファイルを流しながら処理する書き方が必要
  • Next.js を動かすのに変換用の仕組みが要る(今の版で動くかは未確認)

一本化はどちらも「ブラウザの中で動画から音声を取り出して圧縮する」ことが前提です。モノラル・32kbps にすると60分で約14MB、120分で約29MBになります。変換は利用者のパソコンで行うため、1時間の録画で数分かかる可能性があり、スマホや2GBを超える録画には向きません。

使い方ごとの候補

使い方候補理由
自分だけで使う Render(無料)で開始 設定済みで0円。メモリ不足や起動待ちが気になったら Fly.io に移る
クライアントにデモを見せる Fly.io(東京)を常時起動 起動待ちがなく、改修も不要。確認期間が終われば止められる
クライアントが継続して使う Google Cloud Run(東京)
または Fly.io(東京)		 社内審査と国内保管を重視するなら Cloud Run(改修あり)。早さを重視するなら Fly.io
管理を1か所にしたい Cloudflare または Vercel に一本化 書き直しの手間と引き換え。クライアント利用なら Cloudflare のほうが安い

置き場所より先に決めること(クライアントに出す場合)

  • ログインがない: 今は URL を知っていれば誰でも使え、サーバーに入れた API キーの料金がかかります。最低でもパスワードでの制限が必要です。
  • 費用の名義: API キーとサーバーのアカウントを誰の名義にするかで、請求と引き継ぎが変わります。
  • 音声が外部に送られる: 文字起こしと要約のために、音声と文章が外部の AI サービスに渡ります。今は画面の注意書きだけです。
  • 辞書の保存先: ファイルが消えるサービスが多いため、どこに置く場合でも見直しが必要です。

まだ確認できていないこと

  • どのサービスにも、まだ実際にはデプロイしていません。動作・速度・メモリ不足の有無はすべて未検証です。
  • Render の有料プランの月額は、料金ページから読み取れませんでした(仕様は Starter が 0.5コア・512MB、Standard が 1コア・2GB)。
  • Google Cloud Run の無料枠の数字と、東京リージョンの単価は確認できていません。
  • Fly.io の東京の金額は、公式の計算式(基準料金の約1.31倍)から求めた試算です。自動停止時の「数十円」も、月10本・1本15分稼働と仮定した試算です。
  • Cloudflare の無料プランを商用に使ってよいか、Containers が正式版かどうかは、確認したページに記載がありませんでした。
  • ブラウザでの音声抽出は未実装です。変換にかかる時間と、圧縮後の文字起こし精度は試していません。
